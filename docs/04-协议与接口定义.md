# 04 协议与接口定义

> 本文档定义帧格式、序列化协议、核心接口与错误码，是 [02-架构与业务逻辑设计](02-架构与业务逻辑设计.md) 的细化。文中 Go 片段均为**接口示意**，最终以代码生成为准。

## 1. 服务接口定义（用户侧）

### 1.1 定义方式

用户以标准 Go interface 定义服务，实现体注册到框架：

```go
// 服务接口：方法签名固定为 func(ctx, *Req) (*Resp, error)
type HelloService interface {
    SayHello(ctx context.Context, req *HelloRequest) (*HelloReply, error)
    Echo(ctx context.Context, req *EchoRequest) (*EchoReply, error)
}

type HelloRequest struct {
    Name string `json:"name"`
}

type HelloReply struct {
    Message string `json:"message"`
}
```

### 1.2 方法级配置（tag）

```go
type EchoRequest struct {
    Text string `json:"text"`
}

// Echo 方法通过 tag 声明：2s 超时、最多重试 2 次、幂等、使用 json 序列化
func (s *HelloServiceImpl) Echo(ctx context.Context, req *EchoRequest) (*EchoReply, error) {
    // ...
}
// tag 示例（挂在方法所在类型的 tag 元数据表，实现时通过注册选项或类型注册表读取）：
//   echo   : rpc:"timeout=2s,retry=2,idempotent,codec=json"
```

### 1.3 注册与调用

```go
// 服务端注册
srv := server.NewServer(server.Config{Addr: ":9001"})
err := srv.Register(&HelloServiceImpl{}, server.WithServiceName("hello"))

// 客户端调用
cli := invoke.NewClient(invoke.Config{...})
var reply HelloReply
err := cli.Call(ctx, "hello", "SayHello", &HelloRequest{Name: "go-rpc"}, &reply,
    invoke.WithTimeout(3*time.Second), invoke.WithRetry(2))
```

## 2. 帧协议（Wire Protocol）

### 2.1 帧布局

```
┌──────────┬─────────┬─────────┬───────┬────────┬────────┬─────────────┬────────────┬────────────┬──────────────┬──────────┐
│ magic(2) │ ver(1)  │ msgType │flags  │ codec  │ status │  reqId(8)   │ headerLen  │  bodyLen   │   header    │   body   │
│ 0x4A52   │ 0x01    │ (1B)    │ (1B)  │ (1B)   │ (1B)   │  uint64 BE  │ uint32 BE  │ uint32 BE  │ (headerLen) │(bodyLen) │
└──────────┴─────────┴─────────┴───────┴────────┴────────┴─────────────┴────────────┴────────────┴──────────────┴──────────┘
0          2         3         4       5       6       7            15          19          23         23+hLen       23+hLen+bLen
```

**定长头共 23 字节**，各字段：

| 偏移 | 长度 | 字段 | 说明 |
| ---- | ---- | ---- | ---- |
| 0 | 2 | Magic | 固定 `0x4A52`（"JR"），非法帧直接拒绝 |
| 2 | 1 | Version | 协议版本，当前 `1`；版本不匹配返回协议错误 |
| 3 | 1 | MsgType | `0`=Request，`1`=Response，`2`=Ping，`3`=Pong |
| 4 | 1 | Flags | bit0=压缩占位，bit1=携带 TraceID，bit2=元数据扩展占位 |
| 5 | 1 | CodecID | `0`=gob（默认），`1`=json，`2`=binary；3~15 预留自定义 |
| 6 | 1 | Status | 响应状态码，见 §5；请求帧恒为 0 |
| 7 | 8 | ReqID | 请求唯一 ID（大端 uint64），响应回带，客户端按此匹配等待者 |
| 15 | 4 | HeaderLen | Header（JSON）字节长度，大端 uint32 |
| 19 | 4 | BodyLen | Body（codec 编码后）字节长度，大端 uint32 |
| 23 | H | Header | JSON 编码的 `FrameHeader` 扩展字段（见 2.2） |
| 23+H | B | Body | 按 CodecID 序列化后的参数/结果 |

> 最大帧限制：`HeaderLen <= 64KB`、`BodyLen <= 16MB`，超限拒绝，防止内存攻击。

### 2.2 扩展 Header（JSON 编码）

```json
{
  "service": "hello",        // 服务名
  "method": "SayHello",      // 方法名
  "trace_id": "a1b2c3",      // 链路追踪 ID（flags bit1 置位时必填）
  "timeout_ms": 2000,        // 服务端 handler 执行截止时间（ms）
  "meta": {}                 // 自定义元数据（flags bit2 置位时可用）
}
```

### 2.3 编解码规则

- 数值一律大端序；
- Header 固定 JSON 编码（小、可读、与 codec 解耦），Body 用方法配置的 Codec 编码；
- 请求帧的 `status=0`；响应帧必须回带相同 `reqId` 与 `codec`（响应 Body 使用**请求同款** Codec 编码）；
- 帧完整性由长度字段保证，读端按 `headerLen+bodyLen` 精确分片。

## 3. 序列化协议（Codec）

### 3.1 接口

```go
type Codec interface {
    // Encode 将任意 Go 值编码为字节流
    Encode(v any) ([]byte, error)
    // Decode 将字节流解码到 v（指针）
    Decode(data []byte, v any) error
    // Name 返回协议名（gob/json/binary），CodecID 由注册顺序决定
    Name() string
}

// 全局注册表：codec.Register(c) 注册自定义实现
var registry sync.Map // name → Codec
```

### 3.2 三种内置实现对照

| Codec | ID | 编码内容 | 特点 | 适用 |
| ----- | -- | -------- | ---- | ---- |
| gob | 0 | `encoding/gob`，类型信息随流 | 类型安全、Go 原生 | 默认 |
| json | 1 | `encoding/json`，字段名文本 | 可读、可跨语言调试 | 调试/日志 |
| binary | 2 | 自研紧凑二进制：类型标签 + 值 | 体积最小、速度最快 | 性能敏感 |

### 3.3 自研二进制编码（binary）设计

- 标量类型标签：`1`=bool、`2`=int、`3`=int64、`4`=float64、`5`=string、`6`=[]byte、`7`=struct、`8`=slice、`9`=map、`0`=nil；
- string/[]byte/slice/map 均带 4 字节长度前缀；
- struct 按字段序编码，不做字段名编码（要求两端类型一致）；
- 解码端用反射按目标类型读取，类型不匹配返回 `ErrTypeMismatch`；
- 不支持指针环、interface{} 动态类型（返回明确错误）。

## 4. 核心内部接口

### 4.1 注册中心

```go
type Instance struct {
    Service        string            // 服务名
    Addr           string            // host:port
    Weight         int               // 权重（加权轮询用）
    Meta           map[string]string // 附加元数据
    TTL            time.Duration     // 租约 TTL
    LastHeartbeat  time.Time         // 最近心跳（static 实现维护）
    Healthy        bool              // 健康标记
}

type Registry interface {
    Register(ctx context.Context, inst Instance) error
    Deregister(ctx context.Context, inst Instance) error
    Heartbeat(ctx context.Context, inst Instance) error
    Discover(ctx context.Context, service string) ([]Instance, error)
    Watch(ctx context.Context, service string) (<-chan []Instance, error)
    Close() error
}
```

### 4.2 负载均衡选择器

```go
type Selector interface {
    // Select 从实例列表中选出一个；key 为一致性哈希的输入
    Select(instances []Instance, key string) (Instance, error)
}
// 工厂：NewSelector("random" | "roundrobin" | "weighted" | "hash")
```

### 4.3 连接池

```go
type Conn interface {
    Send(msg *protocol.Message) error
    Recv() (*protocol.Message, error)
    Alive() bool      // 活性探测
    Close() error
}

type Pool interface {
    Get(ctx context.Context) (Conn, error)
    Put(conn Conn) error
    Close() error
    Stats() PoolStats // Active/Idle/Capacity/Waiting/TotalCreated/TotalClosed
}
```

### 4.4 调用配置

```go
type CallOptions struct {
    Timeout    time.Duration // 单次尝试超时，0 使用全局默认
    Retry      int           // 最大重试次数，-1 使用方法/服务配置
    Codec      string        // 覆盖序列化协议
    Metadata   map[string]string
    Key        string        // 一致性哈希键
    Idempotent bool          // 幂等标记（决定送达状态不明时是否重试）
}
```

## 5. 错误码与错误传播

### 5.1 Status 码（帧头 status 字段）

| 值 | 常量 | 含义 | 客户端行为 |
| -- | ---- | ---- | ---------- |
| 0 | StatusOK | 成功 | 解码 reply 返回 |
| 1 | StatusClientError | 请求参数/格式错误 | 不重试 |
| 2 | StatusServerError | 服务端内部错误（含 panic） | 可重试 |
| 3 | StatusTimeout | 服务端执行超时 | 可重试 |
| 4 | StatusNotFound | 服务/方法不存在 | 不重试 |
| 5 | StatusUnavailable | 服务端拒绝（限流/关闭中） | 可重试 |
| 6 | StatusProtocolError | 协议层错误（magic/版本/长度非法） | 不重试 |

### 5.2 客户端错误（本地）

| 错误 | 可重试 | 说明 |
| ---- | :----: | ---- |
| `ErrDial` | ✅ | 拨号失败/拒连 |
| `ErrPoolTimeout` | ✅ | 借连接等待超时 |
| `ErrReadTimeout` | ✅（幂等才重试） | 读取响应超时，送达状态不明 |
| `ErrSend` | ✅（幂等才重试） | 发送中断 |
| `ErrDeadlineExceeded` | ❌ | 整体截止时间耗尽 |
| `ErrNoInstance` | ❌ | 发现层无健康实例 |
| `ErrUnknownCodec` | ❌ | 协议配置错误 |
| 业务错误（Resp.Err != nil） | ❌ | 业务已执行 |

### 5.3 错误传播格式

响应帧 Body 在错误时为 JSON 编码：`{"code": 2, "msg": "service error: xxx", "detail": "..."}`，客户端解码后包装为 `*RPCError`，保留 Status 以便分类器决策。
