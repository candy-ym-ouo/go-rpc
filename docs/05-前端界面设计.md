# 05 前端界面设计

## 1. 目标与原则

- **简单**：无构建工具、无 npm、无框架，原生 HTML/CSS/JS，三个静态文件，`go:embed` 编译进二进制；
- **可视**：将框架的四大能力（服务发现、连接池、超时重试、监控指标）以面板形式直观呈现；
- **低侵入**：前端只消费 `pkg/monitor` 提供的 JSON API，不参与 RPC 调用链。

## 2. 技术选型

| 项 | 选择 | 说明 |
| -- | ---- | ---- |
| 页面 | 单页 `index.html` | 顶部导航 + 四个面板区块 |
| 样式 | `style.css` | 深色主题，CSS Grid 布局，无外部字体/图标库 |
| 逻辑 | `app.js` | `fetch` 轮询 API + 手写 Canvas 折线图（不引图表库） |
| 服务 | `pkg/monitor/http.go` | `http.FileServer` 挂载嵌入资源 + JSON API 路由 |
| 刷新 | `setInterval` 5 秒 | 顶部提供手动刷新按钮与间隔选择（2s/5s/10s） |

## 4. 面板细节

### ① 服务发现面板
- 数据源：`GET /api/services`；
- 表格列出所有服务与实例，实例状态着色（在线绿 / 失活灰 / 心跳超时红）；
- 负载策略下拉框：切换 `random / roundrobin / weighted / hash`（调用 `POST /api/config` 生效）；
- 顶部展示在线/失活实例计数。

### ② 调用监控面板
- 数据源：`GET /api/metrics?seconds=1..60`（默认 60，超出范围自动收敛）；
- Canvas 按所选窗口绘制 QPS 与成功率两条折线（双 y 轴）；
- 数字卡片：QPS、成功率、平均延迟、P99、请求/成功/失败/重试/超时累计数；
- 延迟与错误均按窗口累计，轮询时全量重绘。

### ③ 连接池面板
- 数据源：`GET /api/pools`；
- 每个目标地址一行：活跃 / 空闲 / 容量 / 等待数；
- 附连接创建与关闭累计数，用于观察池的回收行为；
- 告警数据源：`GET /api/alerts`，展示 `pool_waiting`（有调用方等待）和 `pool_saturated`（活跃连接达到容量）状态。

### ④ 客户端配置面板
- 数据源：`GET /api/config`；
- 只读展示默认超时、重试、退避、池参数、注册中心与负载策略（支持切换策略，见①）。

## 5. HTTP API 设计

| 方法 | 路径 | 返回 | 说明 |
| ---- | ---- | ---- | ---- |
| GET | `/` | HTML | 前端页面（嵌入资源） |
| GET | `/api/services` | `{"services":[{"name":"hello","instances":[{"addr":":9001","weight":10,"healthy":true,"lastHeartbeat":"..."}]}]}` | 服务与实例 |
| GET | `/api/metrics?seconds=1..60` | `{"qps":128,"successRate":0.992,"avgMs":1.8,"p99Ms":12,"total":64000,"success":63500,"fail":512,"retry":89,"timeout":23,"series":[{"t":171...,"qps":127,"successRate":0.99}]}` | 调用指标与序列 |
| GET | `/api/pools` | `{"pools":[{"addr":":9001","active":12,"idle":38,"capacity":100,"waiting":0,"created":5200,"closed":1100}]}` | 连接池状态 |
| GET | `/api/alerts` | `{"alerts":[{"addr":":9001","level":"warning","code":"pool_saturated","message":"connection pool reached capacity"}]}` | 连接池等待/饱和告警 |
| GET | `/api/config` | `{"defaultTimeoutMs":2000,"defaultRetry":2,"baseDelayMs":200,"jitter":0.3,"poolMax":100,"poolIdleTimeoutSec":30,"registry":"static","selector":"random"}` | 客户端配置 |
| POST | `/api/config` | `{"selector":"weighted"}` | 动态切换负载策略 |
| GET | `/api/healthz` | `{"status":"ok"}` | 健康检查（供 Consul/负载均衡探测） |

**约定**：所有响应 `Content-Type: application/json; charset=utf-8`；错误响应 `{"error":"..."}` 且状态码 4xx/5xx。

## 6. 刷新机制

1. 页面加载即拉取服务、指标、连接池、告警和配置 API 全量渲染；
2. `setInterval` 按所选间隔轮询（默认 5s）；
3. 轮询期间请求失败（如服务端重启）：保留旧数据并在顶部显示"连接中断，N 秒后重试"，不打断用户操作；
4. 折线图维护 60 个数据点的环形数组，每次轮询 push 新点、重绘。
