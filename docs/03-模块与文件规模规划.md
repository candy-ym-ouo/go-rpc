# 03 模块与文件规模规划

本文档是**规模约束的权威依据**，也是后续代码生成的蓝图。代码实现必须严格对齐本规划的包结构、文件清单与行数区间。

## 1. 硬性约束

| 指标 | 约束 | 规划值 | 说明 |
| ---- | ---- | ------ | ---- |
| Go 代码行数（不含测试） | `2000 < 行数 < 2200` | **2150 行**（区间 [2050, 2190] 验收） | 验收按 `find + wc -l` 统计 |
| Go 代码文件数（不含测试） | `20 < 文件数 < 25` | **24 个 .go 文件** | 若需调整：只允许**合并**文件，禁止新增到 25 |
| 测试文件 | 不计入上述统计 | 9 个 `*_test.go` | 见 §6 |
| 前端文件 | 不计入上述统计 | 3 个静态资源 | HTML/CSS/JS，`go:embed` 嵌入 |

> 行数统计口径：`find . -name '*.go' -not -name '*_test.go' | xargs wc -l`，仅统计仓库内 Go 源码，不含 `go.mod`、生成文件与前端。

## 5. 规模控制策略（实现时执行）

1. **行数浮动容差**：单文件实现允许 ±10% 浮动，但整库合计必须落在 (2000, 2200)；代码生成后立即运行 §6 校验命令；
2. **文件数铁律**：24 个文件上限即红线（25 即不合格）。若某包实现需要拆文件，必须**合并同包其他文件**或**精简实现**，绝不允许净增文件；
3. **注释与空行**：统计口径含空行与注释（`wc -l`），因此文档型注释是规划行数的一部分，也是控制浮动的缓冲手段；
4. **不写死代码**：功能点按 [01-项目概述与功能设计](01-项目概述与功能设计.md) 的清单实现，禁止为凑行数添加无用代码；
5. **测试与前端**：`*_test.go` 与 `web/*` 不计入统计，可自由编写。
